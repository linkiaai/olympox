# Video handoff package

Save a new character-local version, such as `influencers/<slug>/work/video-handoff-v001.md`, and register it with the method plan and exact shot files as run inputs/planning outputs. Follow [the procedure](../docs/production-handoff.md). This document uses existing file/hash records; it is not an automatic submission schema. Never overwrite a tracked version or approved input.

## Pilot and delivery decision

- Representative shot selected and why it exercises the character's risks:
- Pilot's real exported bytes / registration, hashes and applicable `execution-seal` / complete review with `approve` / corrections in new versions reviewed and approved again / remaining blockers or required media not inspected:
- Validated settings and evidence applicable to remaining shots; changes needing another pilot:
- Final edit/export files and exact reviewed hashes:
- Publication authorization, actual publication evidence when it occurs, or pending next action:

Do not batch before the pilot's real exported bytes are registered and hashed with the applicable `execution-seal`, and complete review of those exact files records `approve` without blocking issues or required media left uninspected. Corrected versions require complete review and approval again before batches. Keep declared nonblocking limitations. Do not repeat unresolved submissions through another route. Changed observed inputs/tool/method/governance use the existing explicit new-attempt procedure and preserve previous evidence.
