# Production method plan

Copy this template to a new version in the installed studio, such as `influencers/<slug>/work/production-method-v001.md`. For discovery before a character exists, use a local planning file in `work/`. Register the actual file as a run input or a planning output. Do not overwrite a tracked version; a changed method uses a new version and the existing explicit new-attempt procedure. This is a conversational planning document, not a new runtime schema or provider adapter.

Concept, personality, narrative, scripts, and planning stay in ChatGPT/Codex. For new influencers, start visual appearance, candidates, references, settings, images, and edits with **integrated ChatGPT/Codex image generation/editing** when available, unless the user explicitly selects another method/provider. It requires neither Higgsfield/AI Influencer Builder, an external CLI, nor an API key. Select verified tools for voice, animation, video, lip-sync, and specialized needs per stage according to need, quality, and known cost; Higgsfield is optional. Missing capability keeps the stage pending with proposed alternatives; a switch to paid external generation needs applicable authorization. Existing characters preserve approved canon and reuse compatible completed-stage evidence rather than restarting identity creation.

## Stage map

For video, follow [Codex-to-video checkpoints](../docs/production-handoff.md) and save a [video handoff package](video-handoff.md) with readiness, owners and a submission map per shot. Keep the rich inspected library separate from each tool's actual supported input subset.

Keep the complete creative/quality sequence for new influencers and identify which media the objective requires. Record any explicit objective/method choice that makes a stage inapplicable; unavailable tools, absent authorization or metrics leave a required stage pending rather than omitted. Training remains optional. Identify dependencies, exact files/hashes or provider IDs, and actual evidence. Reuse a completed stage only when its evidence and inputs fit the selected method. Actually attach selected exact references to later generation/editing calls; paths in a prompt are not attachments.

Preserve approved canon and original bytes. New provider sheets remain candidates until inspected; adding a provider does not itself change identity or invalidate approval. A neutral sheet checks continuity; the in-character scene checks whether the memorable concept survived generation.

For a new speaking character, prepare the vocal sample with `purpose: reference` while the persona is `draft`, listen and approve its exact reference, then approve/freeze the complete canon before production. Voice settings and approved references contribute to the canon hash; do not append a new voice to the same frozen version. Record voice as not applicable for a silent persona. Reuse unchanged existing approved voice without another approval; a new or changed voice follows normal identity-version evolution.
