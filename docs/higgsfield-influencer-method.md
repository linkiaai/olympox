# Higgsfield reference production method

This guide maps a character concept to a complete media pilot. Codex or Claude Code coordinates research, personality, narrative, scripts and direction. Higgsfield is the default provider for candidates, references, scenes, image edits, voice, animation, video and lip-sync, through operations verified for the current studio.

The [reference study](video-reference.md) explains the source sequence. Its observed image/reference, voice-direction and video stages remain separate from today's selected tools. Save the source mapping and any adaptation in a versioned [production-method plan](../templates/production-method.md); use that plan as a run input or planning output.

## Choose the method and check readiness

Identify the selected modules, deliverables, dependencies, route and existing canon. Check account/workspace, exact-reference transport, voice/listening when needed, export and complete inspection for the whole pilot before the first paid stage. Record scoped quotes, available balance, attempt/correction limits, unknown charges and applicable authorization. Reuse authorization that already covers the work.

Module names describe different operations. Builder prepares character sheets; a sheet is not trained Soul ID, a vocal reference or a video. The source study's Soul Cinema and Seedance labels do not establish current callable availability. Verify required modules separately. If one is missing, keep its stage pending and propose a compatible adaptation. Materially changing the selected provider/method requires the user's decision; [integrated images](integrated-images.md) are an explicit alternative.

## Follow the creative sequence

| Stage | Work and completion evidence |
| --- | --- |
| Discovery and concept | Resolve the brief's gaps; when direction is open, compare three distinct concepts and recommend one. Save audience, personality, visual signature, recurring premise and the selected direction. |
| Visual exploration | Direct expressive candidates and an in-character scene through the chosen verified image/reference module. Record actual outputs, inspection and the user's visual selection. |
| Reference pack | Develop coherent views from the selected candidate using actual reference attachments. Inspect recognition, anatomy, proportions and presence across angles/scenes. Save readable exact files. |
| Voice when speaking | Generate a draft/reference spoken sample, listen and record the user's selection, exact file/hash and voice settings before final canon approval. Silent scope records why voice is not applicable. |
| Complete canon | Approve exact reviewed visual/vocal references and preserve canon version/hash and snapshot through local operations. Compatible existing canon is reused. |
| Script and scenes | Prepare the content/shot list against approved context. Generate required scene inputs with exact references and inspect them before animation. |
| Pilot | Use supported image/audio/motion inputs for one representative piece in the intended medium. Speaking/performance work needs a suitable video pilot before batches. |
| Review and delivery | Export actual bytes, register/seal provenance and completely inspect the final media. Correct failures in new versions and review again. |
| Publication and learning | Publish with applicable authorization; record actual posts/results and compare suitable windows, exposure and cost. Viral potential remains a testable hypothesis. |

Use [strategy](strategy.md) for discovery, [production](production.md) for character/reference decisions, and [video handoff](production-handoff.md) for shot preparation. A tool default is not art direction: direct the selected age, silhouette, appearance, attitude and premise deliberately.

A new speaking character remains `draft` while its vocal sample is prepared with `purpose: reference`. Written voice direction does not replace listening to the sample. Voice settings and approved references contribute to the canon hash; adding a changed voice after freezing canon requires a new version and approval.

## When selected, prepare the Builder with current plugin tools

Read the live tool schemas before use. The operation names below are provider-tool concepts, not OLYMPOX commands or automatic core adapters:

| Operation | Purpose |
| --- | --- |
| `ai_influencer_prepare` | Prepare a sheet design and obtain its returned parameters and scoped quote |
| `ai_influencer_generate` | Submit the prepared sheet design within the applicable allowance/cap |
| `ai_influencer_get_settings` | Retrieve settings from an existing sheet's real job identifier for fresh preparation |

When preserving a design, use confirmed identity references and explicit compatible appearance/tier settings, with `randomize: false` where the live schema supports it. Keep identity inputs separate from Style/item references and respect the actual input limits. Pass the exact returned preparation `params` unchanged to generation with the current cost controls. Confirm free-only eligibility and controls when that is the authorized scope; missing cost does not mean free.

Persist intent before generation, retain every accepted job ID and reconcile its real outcome. Saved settings require fresh preparation and price review; they do not replay a job or restore local canon. Follow [plugin execution](higgsfield-plugin.md) for reference transfer, outcome recording and export. Public website/API parameters do not establish plugin or CLI parity.

## Preserve an approved character

Load its ID, canon version/hash, approval and exact reference files, including approved voice where applicable. A new provider sheet is a derivative candidate: inspect it against canon and retain it as a new version. A provider change does not authorize redesign, replacement of approved references or migration of historical records.

Use confirmed transferred identities in their supported roles and compare new angles/scenes with original canon. Seeds, settings and a successful job do not prove fidelity. An identity evolution requires its own user decision, canon version and approval. Changed tracked inputs, method/provider or governance use an explicit new attempt with a reason; earlier bytes and approvals remain preserved.

## Optional identity training

Consider Soul ID or another training step only when the selected pipeline needs it or the pilot exposes a concrete consistency problem. Verify actual training access, required source images, rights, price, output use and recovery. Record its justification and applicable training authorization separately. A character sheet is not evidence of training, and recurring content alone does not require it.

## Record evidence at each stage

Keep the method/module/route, tool and exposed model, exact prompt/parameters, actually attached files/hashes and provider IDs, outputs, known cost/unit, limitations and actual review. Unknown monetary cost stays `null`; credits remain separate provenance.

Persist external intent before submission and reconcile original jobs before retrying. Register actual local outputs and seal their context. The core preserves records and provider declarations; real tools and inspection establish whether the intended media exists and is usable. Prepared packages, completed jobs and source examples do not demonstrate a successful studio pilot.
